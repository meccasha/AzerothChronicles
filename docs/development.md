# Development

## Prerequisites

Python 3.12+, Node 22+, PostgreSQL 16, `uv`. Docker is optional.

## Backend

```bash
cd backend && uv venv .venv && uv pip install --python .venv/bin/python -e '.[dev]'
```

```bash
createdb azeroth && createdb azeroth_test
```

```bash
.venv/bin/alembic upgrade head
```

```bash
.venv/bin/python -m app.cli seed-demo        # fictional demo group (~30 s, runs the real ingestion pipeline)
```

```bash
.venv/bin/uvicorn app.main:app --reload --port 8000
```

Interactive API docs: http://localhost:8000/api/docs. Configuration comes from environment variables or
`.env` (see `.env.example`).

### Migrations

```bash
.venv/bin/alembic revision --autogenerate -m "describe change"
```

```bash
.venv/bin/alembic upgrade head
```

Review autogenerated migrations before committing. `alembic check` verifies models and migrations agree.

### Management commands

| Command | |
|---|---|
| `python -m app.cli seed-demo [--if-missing]` | (Re)create the fictional demo group |
| `python -m app.cli purge-demo` | Delete all demo data (also set `DEMO_MODE=false` to hide the demo login) |
| `python -m app.cli recompute-awards` | Recompute every group's awards |
| `python -m app.cli sync` | One Battle.net sync pass for all linked users |
| `python -m app.cli worker` | Loop: sync + open-period award recompute every `SYNC_INTERVAL_MINUTES` |

## Frontend

```bash
cd frontend && npm install && npm run dev
```

`/api/*` is proxied to `API_ORIGIN` (default `http://localhost:8000`).

## Demo mode and mock Battle.net

* `DEMO_MODE=true` exposes **Explore the demo group** on the landing page (signs you in as the fictional
  member "Mira Vale"). Demo users cannot log in with a password, create groups, invite, or upload.
* `BLIZZARD_ADAPTER=mock` routes the real Battle.net adapter through an in-process transport that serves
  Battle.net-shaped fixtures (`backend/app/integrations/blizzard/fixtures`). The OAuth flow goes to a local
  "Mock Battle.net" consent page. Switch to `live` with real credentials when ready.

## Simulated game events

Integrations → Import → **Generate simulated events** builds a `source: "simulated"` envelope from your
characters and your group-mates' character names (for roster matching). Edit and import it to see dedup,
wipe streaks, first kills and awards update.

## Tests

```bash
cd backend && .venv/bin/pytest -q tests ../companion/tests
```

The backend suite uses the `azeroth_test` database (override with `TEST_DATABASE_URL`); it drops and
recreates the schema via Alembic, so migrations are tested too. `tests/test_addon_harness.py` executes the
real addon Lua under Lua 5.1 (via `lupa`) against `tests/wow_mock.lua`.

```bash
cd frontend && npx tsc --noEmit && npm test
```

```bash
cd frontend && npm run build && npm run e2e
```

Playwright starts the API and the built web app automatically (or set `E2E_BASE_URL`). It uses whatever
database the API is configured with; the workflow test creates uniquely named users and groups.
